## LanguageConfigSO

Created via `Create > Settings > Language Config`, or `Tools/Localization/Open Language Config`.

| Field | Default | Description |
| --- | --- | --- |
| `sourceFolderPath` | `Assets/Editor/Text Files/Localization` | CSV/XLSX source folder, project-relative. The converter scans it recursively. |
| `soFolderPath` | `Assets/Resources/Localization` | Output folder for generated `LanguageDataSO` assets. Recommended under a Resources folder, with generated assets configured as Addressable. |
| `defaultLanguage` | `zh-Hans` | Primary default language. `LocalizationData.TryGet` records default-language text as the fallback value. |
| `languages` | `zh-Hans`, `zh-Hant`, `en`, `ja`, `ko` | Language column definitions. Drives import, export, Inspector fields and standard headers. |

## LanguageDefinition

| Field | Description |
| --- | --- |
| `code` | Language code. BCP 47 style recommended, e.g. `zh-Hans`, `en`, `ja`. |
| `displayName` | Name shown in the Inspector; inferred from common language codes when empty. |
| `fallbackLanguage` | Language code tried when the current language is missing an entry. |

## LanguageDataSO

Created via `Create > Localization > Language Data`, usually generated by the converter.

| Field | Description |
| --- | --- |
| `sourceFilePath` | Bound source file path. In-project files are stored as `Assets/...`; out-of-project files as absolute paths. |
| `namespaceId` | Optional namespace. Defaults to the asset name when empty. The `Namespace` in templates must match it. |
| `entries` | Localization entries; each has `key`, multilingual `texts` and `comment`. |
| `legacyCsvFile` | Legacy CSV reference migration field; the Inspector tries to convert it into `sourceFilePath`. |

## Source file format

Recommended header:

```csv
Key,zh-Hans,zh-Hant,en,ja,ko,Comment
START_GAME,开始游戏,開始遊戲,Start Game,ゲーム開始,게임 시작,Main menu button
WELCOME,欢迎 {0},歡迎 {0},Welcome {0},{0} ようこそ,{0} 환영합니다,Text with argument
```

Rules:

- The `Key` column is case-insensitive; without a header row, the first sheet (or first CSV column) is treated as `Key`.
- Keys should use `A-Z`, `0-9`, `_`, e.g. `START_GAME`.
- Headered files allow display keys, but runtime use and team collaboration should stick to uppercase snake case.
- Language columns accept language codes, display names or aliases, e.g. `zh-Hans`, `简体中文`.
- The comment column accepts `Comment`, `Comments`, `Note`, `备注`, `注释`, etc.
- Localization placeholders are not allowed inside text content; the editor treats such content as a fatal error.

## Menu commands

| Menu | Behavior |
| --- | --- |
| `Tools/Localization/Open Language Config` | Opens or creates `Assets/Settings/LanguageConfig.asset`. |
| `Tools/Localization/Convert Changed Source Files` | Converts only changed items based on source file and SO hashes. |
| `Tools/Localization/Convert All Source Files` | Forces conversion of all `.csv` and `.xlsx` source files. |
| `Tools/Localization/Validate Duplicate Keys` | Scans all `LanguageDataSO` assets for duplicate keys per namespace. |

## Runtime address resolution

Validated `LanguageDataSO` assets are auto-registered by the editor tooling into the `Localization` Addressables group, with their `NamespaceId` as the address (or the asset name when empty) — no manual setup needed.

Runtime address resolution tries the following Addressables addresses:

- Input contains `/` or `\`: the normalized path as-is; if it is not `Assets/...`, it also tries `Assets/Resources/{path}.asset`.
- Input contains no path separator: `name`, `Localization/name`, `Assets/Resources/Localization/name.asset`.

Therefore the safest setup is keeping `LanguageDataSO.NamespaceId`, the asset name and the Addressables address identical.

## WebGL notes

WebGL players do not support synchronous `WaitForCompletion`. The current public API exposes synchronous lookup only, so this release does not support the first lookup of an uncached namespace on WebGL. A future public asynchronous/preload API is required for that scenario.
